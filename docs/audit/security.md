## 3. Contradictions the orchestrator must reconcile

1. **`reports/SECURITY.md` §3: "No payload crashed the service or produced anything but a structured 4xx" — FALSE.** NaN/Infinity/±1e999 literals and 5000-deep nesting produce 500s (F1, F3). The prior battery tested `10**15` ints (→422) but never non-finite floats or nesting depth.
2. **`reports/SECURITY.md` §8 item 3 implies the chunked gap is covered by proxy config advice.** The shipped `docker/nginx.conf` sets no `client_max_body_size` and does not proxy the API at all (browser → backend direct in compose) — the gap is unmitigated in the default deployment (F2). Fix must be app-side (read-and-count stream) or a compose-topology change.
3. **Prior 500-headers evidence used a test-only `/_boom` route** not present in the tree (`grep -rn "_boom" backend/` → 0 hits). My live evidence uses a genuine in-the-wild 500 — the *claim* (headers on 500) still holds.
4. **F5 (`errors_total` blind spot)** overlaps the monitoring agent's scope — SPEC §10 "request counters, error counts" vs. reality (500s invisible). Reconcile ownership.
