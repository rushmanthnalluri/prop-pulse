## Verdict summary

**PASS.** The live API↔frontend contract holds end-to-end: every field every page parses exists in the served responses with the right JSON type, snake_case throughout, CORS allows exactly the configured origin, 422 error shape matches the client's flattener, and advanced overrides demonstrably reach the model (price moves monotonically with `overall_qual` 4→6→9; override features surface as top SHAP factors). Wave-A frontend-static **F1 (no fetch timeout/abort) is CONFIRMED by execution** — a stalled-but-open API leaves the fetch pending indefinitely (shown >10 s; never settles), i.e. the UI spins forever.

## Non-findings explicitly checked and cleared

- **fallback badge on the default form:** NAmes is a DBSCAN noise point, so the *default* demo prediction always carries `micro_market.fallback:true` → "nearest-cluster fallback" badge. Correct per ADR-9/serve.py:168-185; the fallback cluster_id (0) is in the cluster table, so map/side-panel joins never miss. Not a defect.
- **`sale_probability.sells_within_30_days` consistency:** both branches observed live — default payload `0.2569 ≥ 0.203292 → true`; override payload `0.202214 < 0.203292 → false`. Flag always equals `probability >= threshold` (field-validation check + prediction_service.py:159).
- **estimate inside [low, high]** on all 5 predicts.
- **OPTIONS preflights counted in `/metrics` `requests_by_path["/predict"]`** — all 12 counts on :8400 trace to my own requests; no counter anomaly, no ambient traffic on my port.
- **vite env injection:** served module carries the 8400 base URL, not the :8000 default.
