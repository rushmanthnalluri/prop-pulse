# PropPulse data directory

## Source

`raw/ames/` contains the **Kaggle "House Prices: Advanced Regression Techniques"**
dataset (residential sales in Ames, Iowa, 2006–2010). The dataset was compiled by
Dean De Cock; please cite:

> Dean De Cock (2011). "Ames, Iowa: Alternative to the Boston Housing Data as an
> End of Semester Regression Project", *Journal of Statistics Education*, 19(3).
> https://doi.org/10.1080/10691898.2011.11889627

## How to re-obtain

1. Download the competition archive from
   https://www.kaggle.com/c/house-prices-advanced-regression-techniques/data
   (a Kaggle account is required; the file is `house-prices-advanced-regression-techniques1.zip`,
   already vendored at the repo root).
2. Extract it so the four files land directly in `data/raw/ames/`:
   `train.csv`, `test.csv`, `sample_submission.csv`, `data_description.txt`.

| `sample_submission.csv` | 1,459 | 2 | Kaggle submission template |
| `data_description.txt` | — | — | authoritative NA semantics |

Processed outputs (`processed/{train,val,test}.csv`, `schema.json`,
`outliers_report.json`) are generated by `python -m ml.data.pipeline`
(train YrSold ≤ 2008 / val 2009 / test 2010 — ADR-4). In the processed files,
absent features are stored as the literal string `"None"` and there are no NaNs
anywhere — read them with `pd.read_csv(..., keep_default_na=False)` so pandas
does not turn `"None"` back into NaN.

## Documented fallbacks (ADR-2 / ADR-3)

### 1. Approximate geo centroids (`external/neighborhood_geo.csv`)

The dataset has `Neighborhood` (25 areas) but **no per-property coordinates**.
`external/neighborhood_geo.csv` maps each neighborhood to an **approximate
real-world centroid** in Ames, IA. Centroids were computed as the mean location
of the geocoded 2006–2010 sale locations per neighborhood from the peer-reviewed
companion dataset (Barbour & Fragkias, "Spatializing Ames", *Data in Brief* 63,
2025, doi:10.1016/j.dib.2025.112155), cross-checked against OpenStreetMap named
features. They remain approximations: good enough for neighborhood-level mapping
and micro-market clustering, **not** street-level geocoding. Every point lies
within the Ames bounding box (lat 41.98–42.09, long −93.72…−93.55); city-center
reference is downtown Ames (42.0347, −93.6199).

### 2. SIMULATED days-on-market target

The dataset has **no days-on-market (DOM)** field. `ml/data/sale_speed.py`
simulates `days_on_market` from a transparent, seeded (seed 42) function of real
features — pricing vs. neighborhood median, overall quality/condition, and sale
seasonality — and derives `sells_within_30_days` from it.

**SIMULATED TARGET — NOT FOR MODEL PERFORMANCE CLAIMS.** Classification metrics
against this target measure how well a model recovers the simulation rule, not
real-world sale-speed performance. The module exposes a drop-in `DomProvider`
interface so real DOM data can replace the simulation later without pipeline
changes (see ADR-3).

## Using real days-on-market data

The default pipeline simulates the DOM target (see above). To build the
processed splits from **observed** days-on-market instead, use the
`RealDomProvider` adapter (`ml/data/sale_speed.py`), which the pipeline
selects via two environment variables (`ml/data/pipeline.py`):

- `DOM_PROVIDER`: `simulated` (default) or `csv`;
- `DOM_CSV_PATH`: location of the observed-DOM CSV
  (default `data/external/days_on_market.csv`).

### CSV format

Exactly two columns (extras are ignored), one row per property:

```csv
Id,days_on_market
1,87
2,12
```

- `Id`: the Ames property Id — integer, unique, matching the `Id` column of
  `raw/ames/train.csv`. The file should cover every Id (1–1460).
- `days_on_market`: observed integer days in `[1, 365]`.

Validation is strict: a missing file, missing columns, non-integer dtypes
(floats/blanks/text), duplicate Ids, or out-of-range days are hard errors at
load time. At transform time the adapter checks coverage of each split's Ids
against the file (configurable `min_coverage`, default 0.95): below the
threshold it raises an error listing matched/missing counts — missing Ids
never silently become NaN. The few misses allowed above the threshold are
filled with the median observed DOM and reported via a logged warning.

### Running with observed DOM

```bash
# Git Bash, from the repo root:
DOM_PROVIDER=csv .venv/Scripts/python.exe -m ml.data.pipeline
# custom location:
DOM_PROVIDER=csv DOM_CSV_PATH=/path/to/dom.csv .venv/Scripts/python.exe -m ml.data.pipeline
```

The pipeline logs which provider is active, fails fast with a helpful message
if `csv` is selected but the file is missing, and records the target's
provenance in `data/processed/schema.json`. With `DOM_PROVIDER` unset (or
`simulated`) the pipeline behaves exactly as before and reproduces the
committed processed CSVs byte-for-byte.

### Retrain checklist (the classification target changed)

1. `DOM_PROVIDER=csv .venv/Scripts/python.exe -m ml.data.pipeline`
2. `.venv/Scripts/python.exe -m ml.training.train_classification`
3. `.venv/Scripts/python.exe -m ml.evaluation.evaluate`
4. Verify `models/champion.json`: the classification entry should reference
   the newly trained version with updated metrics.

Note: the "SIMULATED TARGET" caveats in `reports/` and the training/evaluation
module docstrings describe the simulated target and should be revisited when
real DOM data is adopted.
